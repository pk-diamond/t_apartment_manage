🚗 LINE × GAS 駐車場予約システム (Condo Parking Reservation)

マンション管理組合向けの、LINEからシームレスに利用できる来客用駐車場予約システムです。
住民の利便性向上と、管理組合のアナログな管理業務（紙台帳・電話対応）の完全DX化を目的として開発しています。

🎯 プロジェクトの目的と背景

従来の来客用駐車場予約は、管理室に出向いて紙の台帳に記入するか、電話で空きを確認する必要があり、住民・管理人双方にとって大きな負担でした。
本システムは、「住民が普段使っているLINEから、24時間いつでも空き状況の確認と予約ができる」 ことを実現し、予約データをGoogleカレンダーで一元管理することで、管理コストをゼロに近づけることを目指しています。

✨ 主な機能

LINE連携 (LIFF): LINEアカウントによる透過的な認証。煩わしいログインやユーザー登録は不要。

リアルタイム空き状況確認: GoogleカレンダーAPIと連携し、直近2日間の予約状況を視覚的に表示。

日付を跨ぐ柔軟な予約: 「夜間〜翌朝」といった来客ニーズに対応するため、最大24時間・日跨ぎの予約ロジックを実装。

ダブルブッキング防止: 予約実行時にバックエンド側でカレンダーの予定を再フェッチし、秒単位の競合をブロック。

LINEグループ自動通知: 予約完了と同時に、管理組合のLINEグループへ即時通知（Messaging API）。

🏗️ アーキテクチャと技術スタック

本システムは、安定性とセキュリティを最優先し、フロントエンドとバックエンドを完全に分離したアーキテクチャを採用しています。

Frontend: HTML5, JavaScript (ES6+), Tailwind CSS, LIFF (LINE Front-end Framework)

Hosting: GitHub Pages

Backend (API): Google Apps Script (GAS)

Database: Google Calendar

Notifications: LINE Messaging API

💡 こだわり・工夫したポイント

GASの「リダイレクトの罠」を回避するフロントエンド分離
当初はGASの HtmlService を用いたモノリス構成を検討していましたが、GAS特有のURLリダイレクトによりLIFF SDKの初期化がハングアップする問題に直面しました。
これを解決するため、画面描画（フロントエンド）をGitHub Pagesに切り出し、GASを完全な「APIサーバー（バックエンド）」として稼働させる疎結合アーキテクチャへ設計を転換しました。これにより、安定した動作と保守性の高さを両立しています。

CORS制約を突破するセキュアな通信設計
GitHub Pages (フロント) から GAS (バック) へPOSTリクエストを送る際、ブラウザのPreflightリクエスト（OPTIONS）によってCORSエラーが発生します。
これを回避するため、リクエストの Content-Type を意図的に text/plain に設定してSimple Requestとして送信し、GAS側で JSON.parse() を用いてオブジェクトに復元するハックを採用。セキュアかつ確実なデータ連携を実現しています。

モバイルファーストなUX設計 (Tailwind CSS)
LINEアプリ内ブラウザ（LIFF）で操作されることを前提とし、Tailwind CSSを用いてネイティブアプリに近いUIを実装。ローディングアニメーションや非同期処理時のボタン無効化（二重送信防止）、分かりやすいモーダル表示など、細かいUX/UIにこだわりました。

堅牢なバリデーション
「終了時間が開始時間より前になっていないか」「24時間を超える予約ではないか」といったロジックを、フロントエンド（JS）とバックエンド（GAS）の両方で検証（二重チェック）し、不正なデータがデータベース（カレンダー）に書き込まれることを防いでいます。

🚀 導入手順 (Setup)

(※ 実際の運用環境向けの設定メモ)

LINE Developersにて「LINEログイン (LIFF)」および「Messaging API」チャネルを作成。

Google Calendarにて、予約管理用のカレンダーを作成し、カレンダーIDを取得。

本リポジトリの index.html 内の LIFF_ID および GAS_API_URL を環境に合わせて書き換え、GitHub Pagesで公開。

付属の .gs ファイル群をGoogle Apps Scriptプロジェクトに配置し、「ウェブアプリ」としてデプロイ。
